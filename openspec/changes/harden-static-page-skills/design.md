# Design

## Context

参见 proposal.md。当前 builder 检查器只为所选 HTML 返回页面级哈希；publisher 预览核验按 manifest 文件检查，正式核验按 `--page` 选择入口 HTML。两个 skill 的文档也没有定义交接摘要、迁移比较和迁移后合并关口的机器可验证证据。

## Goals / Non-Goals

**Goals:**

- 用标准库生成稳定的产物文件清单和 bundle 摘要，并可在交接时复核。
- 让独立 CSS 的直接本地依赖进入 builder 检查范围。
- 提供不修改工作树的源/目标目录比较工具。
- 让正式核验能选择 manifest 全量文件，并一次性报告多个文件错误。
- 将新证据链写进 builder/publisher 的流程文档和回归测试。

**Non-Goals:**

- 不执行页面 JavaScript，不把静态检查变成完整浏览器或无障碍认证。
- 不自动替用户确认预览，不自动合并 PR，不改变 Pages 触发方式和权限策略。
- 不引入 Node、第三方 Python 包、站点生成器或后台服务。

## Decisions

1. **Bundle 摘要使用规范化文件清单。** 对产物根目录下的普通文件按 POSIX 相对路径排序，记录路径、字节数和 SHA-256，并对规范化记录计算整体 SHA-256。`--output` 位于根目录外，因此不会污染摘要。
2. **CSS 递归复用现有路径解析。** HTML 和 CSS 都通过同一基路径规则解析本地引用；只递归 CSS 文件，维护已访问集合，外部 URL、data/blob 和锚点不下载。
3. **Promotion 比较保持只读。** 新脚本接收两个本地目录，输出 JSON；它不执行 `git mv`，不覆盖目标，也不把用户确认状态写入文件。发布 skill 在迁移后、提交前使用它核对批准源和目标目录。
4. **正式全量核验以 manifest 为准。** 新增 `--all-production`，与 `--page` 互斥；默认轻量模式保持兼容。预览模式继续核验所选任务记录的全部文件。
5. **单文件网络错误聚合。** 只有 manifest/参数结构错误作为全局错误；每个目标文件的请求、MIME、哈希和本地比较错误写入 `files`，继续处理其余目标。
6. **合并关口由 skill 明确。** 迁移产生新 head 后，必须重新运行本地检查，确认候选和 main-ready 检查针对新提交通过，再允许合并；工具不代替用户确认或仓库保护规则。

## Risks / Trade-offs

- [全量核验请求数增加] → 保留页面级模式，并限制单次文件数和单文件大小。
- [CSS 语法不完整] → 只支持稳定的 `url()`/`@import` 识别，遇到复杂动态 CSS 仍明确要求浏览器验收。
- [源目录与目标目录不在同一工作树] → 比较工具输出两侧摘要和逐文件结果，交付记录保留源 SHA 与目标提交。
- [skill 文档与安装副本不同步] → 将源码版本和同步提醒写入文档，并用合同测试检查仓库 skill 入口。

## Migration Plan

1. 先实现检查器、摘要复核、比较器和部署核验器的向后兼容参数。
2. 更新两个 skill、贡献指南和测试。
3. 运行 OpenSpec 严格校验、Python 全套测试和命令帮助检查。
4. 若回退，只需回退本次脚本、skill 和测试变更；不触碰正式页面、预览内容或部署分支。
