静态产物 · PR 预览演示

静态产物预览，一条 PR 就能上线审阅

这个页面是一次预览能力的验证样例：它由 preview/ 分支中的静态文件构建， 通过同仓库 Pull Request 自动部署到独立的临时网址，审阅通过后才迁入正式站点。

📦

纯静态产物

HTML、CSS 与资源自包含，不依赖服务器端程序或数据库，也不在部署环节执行 PR 代码。

🔀

分支隔离

草稿只放在 artifacts/<task>/public/，与正式 docs/ 完全分离，互不污染。

🔗

独立预览网址

按 PR 编号与任务名生成唯一路径，带预览标记与 noindex，公开可直达但不计入正式导航。

🔐

版本可校验

部署记录写入提交 SHA 与文件哈希，可逐字节核对线上内容与审阅版本是否一致。

它是怎么工作的

  1. 准备草稿：在 preview/<task> 分支提交 artifacts/<task>/public/index.html。
  2. 创建 PR：向 main 发起 Pull Request，触发可信工作流。
  3. 自动组合：工作流读取正式站点与全部活动预览，按精确 head SHA 抓取静态文件。
  4. 生成预览：注入可见标记与 noindex，写入 deployment.json，发布到 Pages。
  5. 审阅确认：确认具体版本后，再迁移到正式目录、移除草稿并合入。
本页面为流程演示样例，仅存在于审阅分支，不应合入 main。 正式页面目录见 站点首页。
