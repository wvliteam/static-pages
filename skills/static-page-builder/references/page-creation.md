# 分阶段创建页面

## 输入与视觉方向

从对话、现有文件与项目约定确定内容、读者、日期、来源、所需交互和输出目录。报告可采用“结论 → 证据 → 条件 → 来源”，其他页面按读者任务决定结构，不照搬金融报告。

若已有应用或明确技术栈，遵从项目。独立页面默认可用原生 HTML/CSS/JavaScript，维护源文件可拆开，交付时可内嵌为单文件。只有重复构建有帮助时才新增构建脚本。

设计技能可用时按它的要求检索。检查结果的实际产品类别，不盲目加入不相关的注册、销售或客服流程。可继承现有系统字体、间距、图例和数字样式，但不要求所有页面使用同一行业风格。

## 阶段一：结构与样式

生成可打开的入口页，明确标题、主结论或主要操作和信息层次。源文件、临时数据、日志、截图与最终产物分开；接受任意指定输出目录，不擅自创建 Git 分支或上传。

使用语义 HTML、原生按钮、输入标签与可见焦点。SVG 适合图标和适量历史图表，优先使用可直接缩放的代码素材。

## 阶段二：内容与图表

- 数据带时间、单位和来源。缺失字段如实标注，不以图表装饰补造结论。
- 重要数字由原始数据推导并核对口径。金融场景按需读取 financial-report.md。
- 图例、指标定义和文字读数需帮助读者理解结论。单纯悬停或颜色不能承载全部含义。
- 情景计算器说明不变条件、公式和精度，核对零值、当前值与边界值。
- 来源和计算口径可放在展开区域，日期、核心结论和关键说明保持可见。

阶段内允许清晰标注未完成部分，最终交付前移除占位文本和模板标记。发布系统若需要预览标记，由发布器或工作流注入，不写死到干净的正式源文件中。

## 阶段三：交互与本地验收

按真实行为检查周期切换、时点读数、计算器结果、按钮选中状态等，不用匹配代码字符串代替行为验证。简单内容调整不需要新增测试框架。

本地结构脚本不执行脚本和浏览器布局；按需要补充浏览器验证。建议参考375/768/1024/1440宽度，重点确保无横向溢出、文字可读、键盘操作可用、焦点可见，减少动态效果设置生效。自动检查不等于完整人工无障碍认证。

嵌入站点时使用调用方给出的基路径和资源目录，确认相对路径在嵌套目录中可用；不要在通用技能里固定某个域名或 Git 分支。单文件模式下无须运行时网络字体、脚本或数据接口，用户主动点击的来源超链接可以指向外网。

浏览器不可用时如实说明检查范围。页面自身不要求安装用于验收的浏览器；在线预览由发布器处理，本技能不虚构公网链接。

## 产物交接

交付目录应只含入口 HTML 和运行所需的静态资源。告诉调用方入口、资源清单、数据日期、源文件哈希和检查结果；无需为简单单页强制引入 manifest。后续内容改动须更新检查结果与哈希，不能将旧验证视为新版本验收。
