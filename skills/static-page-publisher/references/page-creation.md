# 分阶段创建页面

## 输入与范围

优先从现有对话与文件确定：要解释的结论、读者、数据来源和日期、是否需要交互，以及在线预览与正式发布各自的授权。用户只要求把既有分析做成网页时，不重新引入未经核验的新结论。账号可用不等于每次都获准上传。

报告优先采用“结论 → 证据 → 关键条件 → 来源”的顺序。其他页面按任务决定结构，不强制套用股票报告。为便于单文件交付，初始技术选择可直接使用原生 HTML/CSS/JavaScript；用户指定技术栈或已有项目时遵从实际项目。

## 设计检索

先读取 UI UX Pro Max，再用该 skill 的绝对路径执行 `scripts/search.py`。新页面先 `--design-system`，按需要补充 `--domain chart` 或 `--domain ux`；只有确实使用对应技术栈时才使用 `--stack`。

每个查询保持一个意图。检查实际返回的产品类别和布局是否适合页面；不合适时按该技能约定收窄一次。仍不匹配就明确采用经过判断的一般建议，不将无关结果保存为“已验证设计”。没有使用的 FAQ、注册、销售 CTA 不必加入页面。新技能默认启用既有自动发现；缺失设计技能时先查找实际路径，不假装执行过。

可以继承已有报告的系统字体、表格数字、语义颜色和间距；新页面不必照搬金融报告视觉。若继承的 MASTER 分类不适用，明确记录页面层面的选择，保留用户认可的视觉结果。

## 阶段一：结构和样式

创建可打开的页面，包含导航、标题、核心结论和有来源的关键数字。先确定移动端优先级，采用语义 HTML、原生按钮和可见焦点。SVG 适合图标、静态图和少量历史数据，无须为了这些元素生成位图。

阶段产物可为：

```text
scratch/<task>/                     # 源文件、构建脚本、数据、检查记录
artifacts/<task>/public/index.html   # preview 分支可审阅产出
```

只有重复构建确有帮助时才写 `build.py`。它负责将样式、数据和脚本合并为 `index.html`；不把源文件路径带到网页中。阶段内尚未完成的部分可明确标注，发布前必须移除占位状态。

在 preview/<task> 分支将可审阅 HTML 写入 artifacts/<task>/public/。构建脚本、原始数据、截图和日志放在 scratch/，不要一并提交到 public。可推送草稿并通过 PR 部署预览，但不要修改正式导航。

## 阶段二：内容与图表

- 先做数据契约：时间、币种、单位、价格精度、复权、估值与实际值。市场日期和采集日期分开。
- 重要数字由原始数据计算，与结论交叉检查。成交量不能写成资金净流向；参考估值不能写成已披露净值；昨天净值不能冒充今天折溢价的分母。
- 分时图保留真实采样点。若压缩午间休市，明确说明；不伪造休市成交。日K与分时的涨跌分母、均线定义、成交量单位分别核对。
- 图表旁放可读结论、图例和文字数据表，避免只能依赖颜色或悬停。
- 情景价格写明固定的其他条件。金融价格的三位小数显示需考虑二进制浮点边界，例如正值可先按价格精度四舍五入，再格式化；测试半个最小报价单位附近的结果。
- 可将来源和计算口径放在可展开区域，主体保持清楚；必要信息在不用脚本时也能阅读。

## 阶段三：交互与验收

按实际功能验证可观察行为，例如切换周期后的数据长度、时点读数、计算器的零值/当前值/边界值、按钮选中状态和打印动作。不要只检查代码含有某些字符串。

优先复用已安装的浏览器能力。检查手机与桌面，建议参考375/768/1024/1440宽度；不要求为简单页面无条件运行全部工具。布局需无横向溢出，正文字号可读，缩放和键盘操作可用，减少动态效果设置生效。自动可访问性检查不等于完整人工认证。

跨目录验证须模拟 `/static-pages/` 基路径，实际点击首页到新页面，再检查图表或关键操作。离线单文件模式下，确认页面加载无需远程字体、脚本、图表库或数据接口；用户点击的来源链接可以指向外网。

### 浏览器不可用时

先复用当前可用工具，不依赖固定机器路径，不将安装浏览器当成用户阅读的前置条件。浏览器不可用时说明检查范围，不将 DOM 模拟器说成真实渲染验收。为需要在线审阅的用户提供已验证的 PR 预览链接；本地文件或 localhost 无法替代它。
