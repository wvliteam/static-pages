## 2. 浏览器环境与隔离方式

初始环境没有可用浏览器。为执行真实浏览器验证，在忽略的 `scratch/site-options/browser/` 中安装了固定 Playwright 1.65.1 及其匹配的 Chromium Headless Shell 159.0.8154.6。

所缺动态库与字体仅从发行版包下载并解包到本地前缀，没有全局安装、改动系统配置或启动 Docker daemon。首次截图发现环境没有字体文件，不能作为视觉证据；补充隔离字体配置后，重新执行全部用例并回读最终截图。

浏览器验证采用文泉驿微米黑与 DejaVu 回退字体。它们仅属于本地验收环境，没有加入网站产物。不同真实终端的字体、系统和浏览器可能产生排版差异。

依据：[Playwright 浏览器管理](https://playwright.dev/docs/browsers)。查询日期：2026-11-21。

## 3. 测试矩阵与请求边界

每条路线检查正式和模拟嵌套两种位置，分别使用 375、768、1440 CSS 像素宽度，共 18 个首页场景。

- 正式 base：`/static-pages/`。
- 模拟预览 base：`/static-pages/previews/pr-999/site-option-<route>/`。
- 每个场景使用独立浏览器 context，减少 localStorage 和缓存串扰。
- 只在环回 HTTP 服务中读取所选产物目录，不开放整个工作区。
- 主题内完整的 `https://wvliteam.github.io` 站内链接，按明确 base 拦截并映射到同一份本地输出；没有通过点击导航读取真实线上页面冒充样例结果。
- 其他外部运行请求主动阻断并记录。
- `pr-999` 仅为路径夹具，不代表已创建 PR。

这项来源映射用于模拟实际域名上的同源导航，未修改产物字节。普通浏览器直接以任意 localhost 路径或 `file://` 打开生成器产物，不具有同样的来源映射，不能据此推定链接兼容。

正式与嵌套截图分别来自匹配 base 的构建；不能用它们证明同一份生成器产物能跨 base 原样迁移。路径负例已在单项文档中单独验证。
