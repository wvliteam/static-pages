## 2. 本轮新增的关键判断

### 2.1 事件兼容性仍有一个实际适用性问题

官方当前说明确认适用公共仓库的默认 PRT 限制节点为 2026-12-02。实际仓库策略列表 API 返回成功空集合；该观察不能证明平台默认策略不会命中本仓库。下一步应核实管理界面或可见 insights，再决定保留现有触发方式或启用备选路线。

实际 Pages 环境允许 main 和 gh-pages 两条分支，不能将当前配置描述为只允许 main。本轮没有修改这些设置。

依据与来源：[R01 的实际配置和官方核查](R01-actions-event-compatibility.md)。

### 2.2 预览有效与 main 就绪需要分别表达

草稿存在于预览分支是正常流程，但 main 禁止跟踪 `artifacts/`。推荐分别提供候选质量检查和 main 合并就绪检查，后者覆盖所有指向 main 的 PR。

预览期 main-ready 失败不应自动导致在线预览被取消。正式迁移并清理草稿后，再满足合并条件。

依据：[R02 的检查设计与隔离试验](R02-pr-validation-ci.md)。

### 2.3 Git 原始 blob 与实际预览输入可能不同

归档导出属性可能删去或替换文件，checkout 属性也可能改变字节。R03 以固定 SHA 的实际 GitHub 归档中干净文件作为确认源，并对首版不支持的归档变换明确失败，避免误证内容相同。

这也影响 R02：仅检查候选 Git 树，不能宣称已验证真实 GitHub 归档输出。

依据与来源：[R03 的归档、字节与目标状态分析](R03-approved-promotion.md)。

### 2.4 正式默认验证的成功范围比整站小

R04 复现确认：现有正式模式默认只请求 manifest 和首页，CSS 损坏时仍可成功；预览模式会校验对应任务的 CSS 并发现错误。建议增加明确的正式资源集合选择。

按 manifest 全量校验，证明的是所有选中文件与记录一致；它不能发现一个从未进入清单、却被运行时错误引用的资源，也不等于浏览器布局或交互已经验收。

依据：[R04 的实际复现与覆盖范围](R04-full-resource-verification.md)。

## 3. 四项方案统一的接口边界

| 契约 | 统一要求 |
| --- | --- |
| 版本身份 | 分别记录事件 base、PR head、候选合并提交、确认源 SHA、正式 main SHA；按检查目的选择，不能混用 |
| 确认依据 | 真实用户授权与文件一致性证据分开；状态字段、CI conclusion 或自生成报告不自动构成批准 |
| 字节身份 | 区分归档干净源、注入后的预览、正式发布文件；不以某一种整体摘要替换所有含义 |
| 路径 | 统一候选、比较和线上校验的可支持路径集合；保留正式 `.nojekyll` 等合法例外，不放宽既有越界限制 |
| 退出码 | 0 为对应操作完整成功，1 为检查或运行失败，2 为 CLI 用法错误；JSON `error_code` 细分原因 |
| 结果范围 | 记录检查的树状态、任务、文件集合和未执行事项；单次结果不自动覆盖其他状态 |
| 副作用 | 候选验证、迁移比较和资源核验均不自行提交、合并或部署；发布流程按现有授权执行 |
| 兼容性 | 保留现有验证器参数和 manifest 字段语义；新能力先实现再写入 skill 的必用调用 |

R03 额外提出 `static-pages-content-tree-v1`，用于相对路径和文件字节集合摘要。R04 当前只需要读取已有逐文件发布哈希，无需为了首版全资源验收先修改部署清单格式。若未来增加源摘要字段，应采用明确的新字段，而不是复用预览生成哈希字段。

首版公共代码应按实际复用程度提取。仓库级候选／迁移工具可以复用仓库辅助函数；独立安装的 publisher 验证器应继续能找到自身依赖，不引入隐含的本机绝对路径。

## 4. 跨项集成时必须处理的条件

### 4.1 R01 备选路线不能直接照搬 R02 的候选 YAML

如果采用低权限 PR 工作流加可信 `workflow_run`：

- R02 示例主要用于候选检查，没有完整覆盖 `closed` 和 base 改离 main 等清理信号。
- 需要额外的可信重建或对账入口，保留 main 手动恢复；是否增加 schedule 按清理时效决定。
- 下游不能只接收上游 `success`，因为正常预览阶段的 main-ready 检查本就会失败。
- 下游只把事件当作对账信号，再由 main 重新查询合格 PR 和精确 head；不执行上游产物。

### 4.2 发布互斥与候选取消采用不同策略

候选验证可以按 PR 取消过期运行；完整站点发布使用统一锁，保留正在进行的部署。

默认 concurrency 不保证所有事件都逐一执行，所以发布可靠性依靠每次重新查询当前源集合。清单记录真实构建版本，后续变化由后续重建收敛。

### 4.3 合并就绪检查不等于确认内容比较

R02 的 main-ready 验证草稿隔离、目录边界等项目规则；R03 验证正式内容与获确认版本的关系。main-ready 通过不能替代后者，也不能替代真实用户授权。

### 4.4 线上前后两次清单核对不提供全局原子快照

R04 建议通过 M1／M2 对照发现已观察到的目标变化，仅比较所选范围及身份，避免其他 PR 更新造成无关失败。CDN 的所有文件读取不因此变成原子事务；结果和交付报告需要保留这个限制。
