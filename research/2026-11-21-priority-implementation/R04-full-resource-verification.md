另一个复现使用相同文件名分别调用当前归档读取与路径校验：

| 文件名 | `archive_files` 接受 | 验证器 `relative_path` 接受 |
| --- | --- | --- |
| `assets/chart.js` | 是 | 是 |
| `assets/chart%20v2.js` | 是 | 否 |
| `assets/chart?.js` | 是 | 否 |
| `assets/chart#v2.js` | 是 | 否 |

## 4. 方案选择

| 方案 | 优点 | 局限 | 建议 |
| --- | --- | --- | --- |
| 根据 HTML 递归推导资源 | 能从页面入口开始收集部分依赖 | 难以完整处理 CSS、动态导入、JS 拼接、条件加载、外部资源 | 作为静态／浏览器检查的补充 |
| 按 manifest 的目录集合校验 | 文件集合明确，可包含二进制和动态加载数据 | 目录外共享资源需要额外选择 | 适合任务级正式验收 |
| 按 manifest 的全部正式文件校验 | 覆盖清晰，减少遗漏 | 文件规模增长后请求量增加 | 首轮正式发布推荐使用 |
| 运行浏览器观察加载失败 | 能覆盖实际交互及运行时资源请求 | 受环境和操作路径影响，也不能自动穷尽所有状态 | 独立的页面行为验收 |

推荐采用 manifest 集合方案。结构检查、资源哈希与真实浏览器验收保留各自的结果，避免把单项通过解释成全部验收完成。

## 5. 拟议命令行契约

以下为新增接口设计，尚未实现；现有调用方式见 [使用指南](../../CONTRIBUTING.md)。

### 5.1 正式模式选择器

| 选择器 | 语义 | 参数规则 |
| --- | --- | --- |
| 无选择器 | 沿用首页 HTML 校验 | 等价于现有默认行为 |
| `--page` | 重复选择 HTML 或含入口的页面目录 | 保持现有 `page_path` 语义 |
| `--prefix` | 重复选择正式文件清单中的目录子树 | 与 `--page`、`--all` 互斥 |
| `--all` | 选择 `production_sha256` 全部文件 | 不包含预览文件和清单之外的生成文件 |

目录前缀按目录段匹配。例如 `pages/example/` 可以匹配其入口和资源，不可以误选 `pages/example-old/`。对重复前缀去重；对嵌套前缀取并集；零匹配返回明确失败。

`--prefix` 的路径相对于站点正式根目录，不包含域名或 `/static-pages/` URL 基路径。根范围使用 `--all`，减少 `.`、空字符串、`/` 的歧义。

### 5.2 保留的兼容行为

- 正式模式仍需完整的 `--main-sha`。
- 预览仍需正数 `--preview-pr` 和完整 `--preview-sha`；可指定 `--task`。
- 预览模式继续拒绝 `--local-root` 和正式模式选择器。
- `--local-root` 对所选正式文件逐字节比较；不隐式检查选择范围之外的本地文件。
- 保留 `--timeout`、`--output` 和现有 `ok`、`mode`、`main_sha`、`files` 字段。
- 路径集合与哈希集合来自 manifest；不执行远端脚本，不携带 GitHub token。

对于目录外共享资源，可重复选择相应前缀，或使用 `--all`。结果必须记录选择范围，不能把某个目录的通过结果标为整站通过。

## 6. 推荐内部实现

### 6.1 功能拆分

| 责任 | 拟议逻辑 | 说明 |
| --- | --- | --- |
| 清单读取 | `load_manifest` | 限制大小，解析并保留原始字节哈希 |
| 结构与路径验证 | `validate_manifest` | 校验版本、类型、路径、哈希与所选任务唯一性 |
| 选择资源 | `select_targets` | 根据页面、目录或全部模式构造排序后的资源集合 |
| 核验单文件 | `verify_file` | 请求、限流式读取、计算哈希、可选本地比较 |
| 汇总错误 | 结果对象与每文件状态 | 保留已检查、失败、未执行的证据 |
| 目标稳定性 | `compare_target_snapshot` | 再读取 manifest，比较目标身份与集合 |

函数名为实现建议，不要求新增公共 API。首版可继续保留在现有独立脚本中，避免让可安装 skill 依赖仓库外的公共模块路径。

### 6.2 清单验证

- 对 root、正式哈希表和所选预览记录验证预期类型。
- 验证 SHA 的格式；文件路径使用现有严格规则并补足 `.` 等非文件键的拒绝。
- 保留合法的 `.nojekyll` 文件键，不能把正式模式路径限制简单等同于预览隐藏文件限制。
- 禁止 query、fragment、绝对路径、反斜杠、百分号编码和路径归一化歧义继续生效。
- 解析 JSON 时拒绝重复键，避免同一文件存在多个哈希却被默认解析器静默覆盖。
- 未知的新增字段可以忽略；不把新增结果字段变成旧部署 manifest 的必填字段。

Python 默认 JSON 解析会接受重复名称并保留最后一个值，可使用 `object_pairs_hook` 实现明确拒绝。依据：[Python JSON 官方说明](https://docs.python.org/3.10/library/json.html#repeated-names-within-an-object)。

### 6.3 文件下载与比较

1. 验证全部目标路径及哈希，再开始下载，避免发现非法后缀前已经执行部分无效请求。
2. 文件顺序固定，首版顺序执行，便于预算控制和复现。
3. 继续以 GET 获取真实字节，不用 HEAD、ETag 或内容长度代替哈希。
4. 可以按块计算 SHA-256；即使响应没有可信的 `Content-Length`，也执行实际读取上限。
5. 明确请求 identity 内容编码；对未支持的内容编码明确报错，避免把压缩表示直接与源文件字节比较。
6. HTML 保留内容类型检查；二进制资源首先按字节校验，避免不必要的严格 MIME 白名单影响兼容性。
7. 使用本地比较时，对路径解析与目录越界进行检查；记录本地文件哈希，保留本次比较证据。
8. 发现内容差异仍按失败报告，不因 HTTP 200 而成功。

### 6.4 建议预算

| 项目 | 当前值或建议值 | 处理方式 |
| --- | --- | --- |
| manifest 大小 | 保留 2 MiB | 超限失败 |
| 单文件大小 | 保留 20 MiB | 实际读取时计数 |
| 所选文件数 | 保留 1000 | 不通过抽样将超限变为成功 |
| 整次下载字节 | 首版建议新增 100 MiB 总预算 | 属于拟定默认值，实施时依据站点规模回归定稿 |
| 请求超时 | 保留现有 1–60 秒参数范围 | 不解释成整次运行硬时限 |
| 整次运行时间 | 由调用方／workflow 限制 | 后续如新增总时限，需对阻塞读取实测 |

`urlopen(timeout=...)` 针对连接等阻塞操作，不能据此承诺整个多文件验证会在同样秒数内结束。依据：[Python urllib.request 官方说明](https://docs.python.org/3.10/library/urllib.request.html#urllib.request.urlopen)。

## 7. 缓存、重定向和版本变化

### 7.1 缓存处理

保留 `Cache-Control: no-cache`，并记录必要的 `Age`、`ETag`、`Last-Modified` 等诊断信息。它们用于解释缓存状态，判定成功仍以目标 SHA 和文件哈希为准。

RFC 9111 中的请求 `no-cache` 表达了使用已存储响应前应成功验证的客户端偏好，不构成“本次一定从源站读取最新文件”的独立证明。依据：[RFC 9111 §5.2.1.4](https://www.rfc-editor.org/rfc/rfc9111.html#section-5.2.1.4)。

带版本查询参数的请求可作为诊断，但最终结果必须说明验收的交付 URL，不能只以带参数地址通过替代普通网址结果。

### 7.2 重定向边界

当前 `urlopen` 默认支持重定向；实验确认跨端口目标返回相同字节也会通过。推荐首版对重定向加入明确检查：

- 保留站点内正常目录入口归一化。
- 拒绝 HTTPS 降级为 HTTP、跨来源或离开已声明站点基路径的重定向。
- 对所有跳转逐次检查并限制次数；不能仅在已经跟随之后检查最终 URL。
- 自定义域名用户应直接提供实际 canonical base URL；初始站点地址重定向的兼容需求另以明确配置处理。

这些属于拟议的站点范围约束。当前代码没有该限制，实施时需补充兼容测试，不能将现有记录 `final_url` 等同于已经约束重定向。

依据：[Python HTTPRedirectHandler 官方说明](https://docs.python.org/3.10/library/urllib.request.html#urllib.request.HTTPRedirectHandler)。

### 7.3 两次清单读取

单次验收的建议流程：

1. 读取 M1，校验目标 main SHA 或 preview SHA。
2. 固定所选路径和哈希表，按该快照验证全部文件。
3. 读取 M2，重新选择同样的目标范围。
4. 比较目标身份、所选路径集合与哈希；任何变化都报告 `deployment_changed`。
5. 只有文件全部通过且目标快照未变，才返回 `ok=true`。

正式模式比较 main SHA 与本次选择范围；预览比较目标 PR／任务的 head SHA 与文件哈希。其他 PR 预览变化不应单独使目标任务失败；若调用方另外指定 main SHA，则也核验它。

两次读取可以发现已观察到的变化，不能证明 CDN 多请求在任意瞬间具备原子一致性，也不能排除中间变化后又恢复的情况。结果准确表述为“本次观察范围内目标稳定且所有选中文件匹配”。若未来需要不可变部署地址，应单独评估发布架构。

## 8. 结果与错误契约

保留现有外层兼容字段，建议新增：

| 字段 | 含义 |
| --- | --- |
| `result_schema_version` | 本地验证结果格式版本，不是部署清单版本 |
| `selection` | 选择方式、目录／页面与所选文件数 |
| `expected` | 调用方传入的目标版本 |
| `observed` | M1／M2 的实际版本与目标快照标识 |
| `files[]` | 原有记录加每文件状态和明确错误原因 |
| `errors[]` | 全局或按文件归属的错误，保留部分结果 |
| `limits` | 实际生效的文件、字节和超时预算 |
| `coverage` | 页面 HTML、指定目录、全部正式文件或选中预览任务 |

建议错误分类包括：`manifest_invalid`、`unsafe_path`、`selection_empty`、`limit_exceeded`、`source_version_mismatch`、`http_error`、`network_error`、`hash_mismatch`、`local_mismatch`、`redirect_out_of_scope`、`deployment_changed`。

首版继续遵循：

- 退出 0：所选范围全部通过。
- 退出 1：校验、网络或内容失败；具体原因由 JSON 表达。
- 退出 2：参数错误，沿用 argparse 语义。

普通文件差异可以继续收集后续结果；清单非法、预算耗尽等问题停止相应后续请求，并将尚未执行项明确标记为未执行。输出目录继续位于被发布内容之外。

## 9. 等待与重试建议

验证器保留单次事实检查，publisher 调用方根据 workflow 状态和失败类型决定是否再次执行：

| 情况 | 推荐动作 |
| --- | --- |
| 清单或文件路径非法、参数错误 | 立即报告，不盲目重试 |
| 认证／权限错误 | 报告实际失败，先解决权限条件 |
| 网络超时、短暂 5xx | 在明确次数或总时限内重新执行 |
| 目标 workflow 尚在运行、线上仍为其他版本 | 调用方有界等待，并持续绑定原目标版本 |
| workflow 已结束但文件哈希错误 | 保留失败证据，定位内容或传播问题；不能自动接受其他版本 |
| 验收中目标版本变化 | 报告变化，重新明确要验收的提交；不静默换成最新版本 |

单凭“SHA 不匹配”不能断言平台仍在部署，也可能是目标已被其他版本替代。验证器不需要为此额外获得 GitHub 凭据。

## 11. 验收矩阵

| 组别 | 必测场景 | 预期 |
| --- | --- | --- |
| 兼容 | 旧命令、默认首页、重复页面、预览任务 | 原语义保留，覆盖范围可见 |
| 全量 | HTML 正确，CSS／JS／图片／JSON 任一损坏 | 退出 1，指出具体文件 |
| 集合 | 嵌套与重复前缀、零匹配、相似目录名 | 去重，零匹配失败，无跨目录误选 |
| 共享资源 | 页面目录外共享资源 | 通过明确追加范围或全量覆盖 |
| 路径 | 越界、编码、query、fragment、特殊文件名 | 在下载前按统一契约处理 |
| 清单 | 错类型、重复 JSON 键、非法哈希、过大清单 | 明确失败并保留错误类型 |
| 本地 | 文件缺失、字节变化、符号链接越界 | 本地比较失败，不掩盖线上结果 |
| 重定向 | 正常目录入口、跨来源、降级、跳出基路径 | 仅支持明确允许的跳转 |
| 变化 | M1／M2 之间版本、路径或哈希变化 | `deployment_changed` |
| 无关变化 | 其他 PR 更新但目标 preview 不变 | 目标核验可继续通过 |
| 预算 | 20 MiB 边界、文件数、无长度响应、总字节 | 不超限读取后继续报成功 |
| 证据 | 已检查两项后发生 HTTP 异常 | 已完成记录保留，剩余项未执行 |

本地 fixture 测试不代替 GitHub Pages 实际版本验收；线上哈希测试不代替浏览器布局与行为检查。
