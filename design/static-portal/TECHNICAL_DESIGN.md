# 直接静态门户技术设计

- 日期：2026-11-22。
- 决策：采用 Start Bootstrap Personal 的直接静态门户路线，保留独立 HTML 报告和工具。
- 分析基线：`ee180b1e36d71b600f324ddbaa8d64e493862565`；当前文档不代表门户已正式收录。
- 文档入口：[设计与实施索引](README.md)。

## 1. 目标与首版范围

首版提供“页面集”的统一入口、报告目录、工具目录和站点说明。已有报告继续以原始独立页面提供，不嵌入新模板，不刷新历史数据，不更换路径。

技术形态保持为可直接部署的 HTML、CSS、JavaScript 和静态资源。页面文件本身是维护源，不引入 Jekyll、Hugo、Pug、SCSS 或 Node 构建步骤。保留已有 builder、publisher 两个 skill 及可信 main 发布边界。

本轮设计不增加博客引擎、站内全文搜索、联系表单、评论、访问统计、登录或服务器端存储。后续新增真实普通页面时，仍使用仓库已有的 `pages/<slug>/index.html` 约定。

依据：[仓库说明](../../README.md)、[工作约定](../../AGENTS.md)、[Personal 实测](../../research/2026-11-21-site-options/03-static-personal.md)。

## 2. 已有证据和采用边界

| 项目 | 已有证据 | 本设计如何使用 |
| --- | --- | --- |
| 模板 | Personal 固定提交 `6a1ebcc76a93ead054412fcbdf417d9c83dc762b`，产物头版本 1.0.1 | 复用布局、CSS 和必要交互，明确保留来源 |
| 依赖 | PoC 使用 Bootstrap 5.2.3 bundle，并保留 Bootstrap、Popper 许可 | 首版优先沿用已验证固定版本；升级作为明确变更重新回归 |
| 路径 | 同一套相对链接产物在正式和嵌套 base 下通过检查 | 沿用可搬迁静态文件方式，按最终目录深度重新验收 |
| 内容 | 既有报告原样复制，SHA-256 未变 | 旧报告作为受保护内容保留 |
| 浏览器 | PoC 已做基础布局、菜单、焦点及入口检查 | 作为可行性证据；新目录和最终页面仍重新验收 |

PoC 中的 `reports.html`、`notes.html`、`about.html` 和两篇测试文章只是研究样例。首版生产路由按本设计重新组织，不将测试文章或旧目录结构整体搬入正式站点。采纳技术路线不等于已经批准样例首页的具体文案和视觉版本。

## 3. 页面与信息架构

| 页面 | 正式源路径 | 相对于站点的 URL | 首版内容 |
| --- | --- | --- | --- |
| 门户首页 | `docs/index.html` | `/` | 用途说明、报告／工具入口、真实精选内容 |
| 报告目录 | `docs/pages/reports/index.html` | `pages/reports/` | 已正式收录的报告，按日期倒序 |
| 工具目录 | `docs/pages/tools/index.html` | `pages/tools/` | 已正式收录的工具；当前显示明确空状态 |
| 关于本站 | `docs/pages/about/index.html` | `pages/about/` | 站点用途、快照说明、来源及仓库入口 |
| 历史报告 | `docs/reports/<symbol>/<date>/index.html` | 原路径保持 | 原始独立报告 |
| 后续工具 | `docs/tools/<slug>/index.html` | 原约定保持 | 工具本身独立实现 |

顶部导航固定为“首页、报告、工具、关于”，四个门户页面保持相同标签和目标。目录页属于普通页面，因此放在 `pages/<slug>/`；工具目录与真正工具的 `tools/<slug>/` 分开。

### 3.1 首页

- 沿用 Personal 的导航、网格、按钮和卡片作为起点，按内容调整比例和文案。
- 不使用未经提供的个人照片、履历、联系方式或成绩指标。
- 精选区只放真实正式内容，首版包含现有 513310 报告；不展示研究用“模板接入验证”等文章。
- 若展示数量，分别显示真实报告数、工具数。首页、目录和关于页不充当新增内容数量。
- 工具数为零时给出“暂无已收录工具”等明确空状态，不提供 `#!`、空链接或虚假可用按钮。

### 3.2 目录与历史内容

报告条目至少包含标题、标的或主题、报告日期、简短说明和真实链接。新增说明沿用已有核验内容，不借更换门户重做行情分析。

工具条目在真实工具通过预览确认、正式收录后再添加。报告、工具内部的图表和计算逻辑不由门户修改；门户 CSS 和脚本也不注入这些独立页面。

首版手工维护有限的 HTML 条目，并将所有聚合入口列入新增内容检查。等数量或更新频率形成实际负担后，再决定是否增加单一目录数据源；本版不先建设生成器。

## 4. 文件布局与资产管理

以下为拟议生产结构，尚未创建这些正式文件：

```text
docs/
  .nojekyll                              # 保留现有正式控制文件
  index.html
  pages/
    reports/index.html
    tools/index.html
    about/index.html
  assets/portal/
    favicon.ico
    vendor/personal/styles.css
    vendor/bootstrap/bootstrap.bundle.min.js
    css/portal.css
  licenses/portal/
    startbootstrap-personal-LICENSE.txt
    bootstrap-LICENSE.txt
    popper-LICENSE.txt
  reports/<symbol>/<date>/index.html       # 保留已有内容
  tools/<slug>/index.html                  # 有真实工具时存在
```

### 4.1 样式与交互

- 第三方样式保留版权头和版本；自有小范围适配集中在 `portal.css`。
- Bootstrap bundle 只用于门户需要的导航行为；不引入空的扩展 JS 文件。
- 字体采用系统字体回退；首版无 Google Fonts、图标 CDN、统计或表单运行请求。
- 图标使用已有必要资源或少量语义明确的本地 SVG；保留按钮文本、标签和可见焦点。
- 所有门户资源位于 `assets/portal/`，避免与报告、工具已有文件冲突。
- 不给历史报告统一套壳，不全站替换字体或公共样式。

### 4.2 来源与升级

后续实施增加根目录维护记录 `third_party/portal/UPSTREAM.md`，记录固定上游提交、依赖版本、原始与本地文件映射、自有修改及许可清单。该位置是维护资料，不进入网站目录。

公开产物保留必要许可文件及页面来源入口。升级时先在隔离目录比较明确的新版本，再重新应用自有适配、运行静态与浏览器检查，不能重新执行上游构建覆盖已维护 HTML。

此处版本为实测基线，不表示它们是最新版本或已完成安全审计。实际采用前的版本复核列入实施任务。

## 5. 链接与可搬迁约束

资源和站内导航均采用相对链接。普通来源超链接和仓库链接可以是明确的 HTTPS 地址；它们不作为运行时资源依赖。

| 起点 | 到首页 | 到门户 CSS | 到现有报告 |
| --- | --- | --- | --- |
| `index.html` | `./` | `assets/portal/css/portal.css` | `reports/513310/2026-11-20/` |
| `pages/reports/index.html` | `../../` | `../../assets/portal/css/portal.css` | `../../reports/513310/2026-11-20/` |
| `pages/tools/index.html` | `../../` | `../../assets/portal/css/portal.css` | 按需要使用同样的站点根映射 |
| `pages/about/index.html` | `../../` | `../../assets/portal/css/portal.css` | 按需要使用同样的站点根映射 |

不写死 `/static-pages/`、真实 PR 编号、域名根路径或 `<base>` 标签。CSS 内 `url()` 相对于 CSS 文件解析，需要单独核对。

同一批干净文件需要在以下位置验证：

1. 正式站点 `/static-pages/`。
2. 实际预览 `/static-pages/previews/pr-<实际编号>/static-portal/`。

本地夹具可以先使用模拟编号，但不能作为线上预览地址交付。路径不同不触发重建或改写源 HTML；工作流按既有逻辑注入的预览横幅和 `noindex` 与干净源哈希分开处理。

## 6. 门户预览的完整快照

门户属于站点根入口更新，预览需要能走通目录和旧报告。建议采用单任务 `artifacts/static-portal/public/`，制作完整的可浏览站点快照：

1. 固定当前正式 main SHA，记录 `docs/` 文件清单与哈希。
2. 将当时已批准的正式静态内容复制到候选根，保留相对层次与字节。
3. 仅排除已知部署控制文件 `docs/.nojekyll`，由现有部署流程处理。当前预览读取器拒绝隐藏成员，不能把它原样提交到 public。
4. 确认不存在 `previews/`、`artifacts/`、`deployment.json` 等保留路径或临时文件。
5. 在候选中覆盖首页，新增本设计的目录、关于页及命名空间资源。
6. 对旧报告和候选非门户文件验证哈希；对整个候选执行静态、路径和浏览器检查。

预览候选中的旧报告是供导航验证的正式内容副本，正式发布时不重新覆盖旧报告。快照超过现有大小或文件数量限制时，应调整本次任务范围和审阅方式，不能绕过发布器限制。

## 7. 正式收录采用受控增量

### 7.1 门户写入范围

首版允许正式改变的网页范围为：

- `docs/index.html`。
- `docs/pages/reports/index.html`。
- `docs/pages/tools/index.html`。
- `docs/pages/about/index.html`。
- `docs/assets/portal/` 中本次明确列出的文件。
- `docs/licenses/portal/` 中本次明确列出的许可文件。

维护资料可以包含 README、使用指南、来源说明及必要 skill 指引的明确修改。所有额外路径都在 diff 中单独解释，不能用目录通配符掩盖其他内容变更。

### 7.2 收录过程

1. 记录真实确认的预览 head SHA，并从该版本读取干净源文件。
2. 对门户写入清单中的全部路径和字节做比较，包含 CSS、JS、图标和许可，不只检查 HTML。
3. 检查当前 main 相对预览基线的变化；门户文件或其依赖发生冲突时重新准备对应候选。
4. 仅将确认过的门户文件按一一映射写入正式位置。完整快照中的其余文件不覆盖回 `docs/`。
5. 保护所有旧报告、工具及其他任务文件；新出现的无关 main 内容也不得被删除。
6. 更新必要导航、数量和正式列表，清理当前任务已跟踪的 artifacts，检查最终候选树。
7. 合入后记录实际 main SHA，执行当次部署及正式验收。

禁止把整个 public 目录直接替换已有 docs，或以全量目录同步删除目标中不存在于旧快照的内容。多个本地比较样例也不应被顺手暂存、删除或带入 main。

无关 main 内容新增不自动撤销用户对相同门户字节的既有授权；如果门户、入口、依赖或可见内容发生实质变化，则按现有规则提供对应版本复核。

## 8. 发布与验证的最小衔接

保留现有 trusted-main 组合站点、生成分支与官方 Pages 部署步骤。门户本身不要求发布 job 安装模板构建依赖，也不执行候选分支的构建脚本或页面 JavaScript。

- 事件策略兼容性：实施开始时重新核对实际配置，引用已有 R01 研究作为起点，不把 2026-11-21 的调查当作当前配置证明。
- 候选 CI：采用 R02 的低权限思路，分别表达静态候选有效和 main 合并就绪。预览分支含 artifacts 时暂不可合并是正常阶段，不阻止受信流程提供预览。
- 确认比较：首版使用明确文件清单和逐文件 SHA-256 记录即可，不要求先实现通用 R03 比较框架。
- 线上验收：现有预览模式覆盖选中任务的全部记录文件；正式模式只验证所选 HTML，资产需要另外按 manifest 与本地文件检查。

正式资源核对可以先使用一次性、只读的检查记录完成。若该操作稳定重复，再将 R04 的全资源模式作为独立增强；不在设计中假设 `--all` 已实现。

对接依据：[R01](../../research/2026-11-21-priority-implementation/R01-actions-event-compatibility.md)、[R02](../../research/2026-11-21-priority-implementation/R02-pr-validation-ci.md)、[R04](../../research/2026-11-21-priority-implementation/R04-full-resource-verification.md)。

## 9. 内容维护与数量口径

新增报告时创建新的日期快照，验证内容后更新报告目录、需要展示的首页卡片和 README 正式列表。新增工具时创建独立工具目录，并在工具目录收录。普通页面遵从 `pages/<slug>/`，按需要增加入口。

首版保留显式 HTML 清单，不运行时扫描目录，不调用 GitHub API 填充卡片。更新清单与正文处于同一次内容变更中，避免页面上线但入口遗失。

数量只统计真正被目录收录的内容条目：报告数、工具数分别核对；门户导航页、许可文件、研究样例和未批准预览不计入这些数量。没有必要时不展示全站总数。

四个门户页面手工维护同一套导航。修改公共导航或自有 CSS 时，全部门户页面一起检查；不为四页引入额外模板编译系统。

## 10. 回退与后续扩展条件

门户发布作为范围明确的提交，出现问题时用新的定向撤销或修复提交恢复相关门户文件。保留发布后新增的报告与工具；新增资产是否可删除，先确认没有其他正式内容引用。

事件策略或 CI 的维护改动单独提交，门户回退不顺便撤销仍然必要的基础设施修复。完整部署失败时保留失败证据，不将 gh-pages 更新等同于线上成功。

当 Markdown 成为主要写作形式、手工目录维护产生明确负担时，再评估 PaperMod 或轻量目录数据源。届时重新确定源码、构建和确认对象；本次不预先兼容多套生成器。
