# 直接静态门户验收与交付标准

- 日期：2026-11-22。
- 对应：[技术设计](TECHNICAL_DESIGN.md)、[实施计划](IMPLEMENTATION_PLAN.md)。
- 本文定义后续实施验收。历史 PoC 结果见 [统一验证记录](../../research/2026-11-21-site-options/VALIDATION.md)，不能代替新门户版本的结果。

## 1. 分层证明范围

| 层次 | 检查对象 | 通过能证明什么 |
| --- | --- | --- |
| 内容与范围 | 文案、条目、数量、变更路径 | 展示实际正式内容，修改局限于任务范围 |
| 本地静态 | HTML、链接、资源、目录、文件哈希 | 已覆盖的结构和文件关系成立 |
| 浏览器 | 门户页面、导航、手机菜单、焦点、截图 | 已执行场景的布局和行为正常 |
| 预览部署 | 实际 PR SHA、任务文件、生成后哈希 | 用户看到的预览对应明确版本 |
| 正式收录 | 确认源与正式增量、受保护文件 | 收录内容与授权版本对应，无无关覆盖 |
| 正式部署 | 目标 main、线上 HTML 与资源字节 | 本次选中文件实际匹配目标版本 |

各层分别记录结果，不用 CI 成功替代用户确认，不用静态检查替代浏览器，不用 HTTP 200 替代版本和字节核对。

## 2. 内容和路径验收

| 编号 | 用例 | 通过条件 |
| --- | --- | --- |
| A01 | 首页、报告、工具、关于 | 路由分别为根入口与三个 `pages/<slug>/` 页面，导航目标一致 |
| A02 | 当前唯一报告入口 | 标题、日期和链接沿用真实报告，原路径可访问 |
| A03 | 工具目录为空 | 清楚说明没有已收录工具，没有假按钮、假数量或占位链接 |
| A04 | 研究内容清理 | 不把两篇模板测试文章、默认人物、联系表单或 token 带入门户 |
| A05 | 资源命名空间 | 门户资源集中在 `assets/portal/`，不改历史报告样式或脚本 |
| A06 | 数量口径 | 报告、工具条目分别核对，导航页和预览不计为真实内容 |
| A07 | 来源与许可 | 固定版本、文件映射、必要许可和来源入口可查 |

首版每个新增页面都需要非空 title、viewport、主内容区、合理标题结构和有意义的链接文字。空状态属于有意设计，不能以模板占位文本代替。

## 3. 文件保全与源字节

实施前记录正式 main SHA、文件清单及哈希。至少单独保护：

```text
docs/reports/513310/2026-11-20/index.html
SHA256=e7fbd1ecd16e6395a07adf1d6026ef3b81d5d8f6a1bc6d739a7227ab8867ddc2
```

本次门户工作不更改该历史报告。如未来实施时 main 有新的、独立批准的变化，应记录新的明确基线，不能用老哈希覆盖或恢复其他任务内容。

必须区分：

- 门户受管文件：确认后允许写入正式位置的明确清单。
- 快照镜像文件：仅用于完整预览的已有内容副本，发布时不反向覆盖 main。
- 部署控制文件：`.nojekyll` 留在正式源；候选 public 不包含这个隐藏成员，部署流程自行处理。

确认源哈希以实际被预览发布读取的干净归档字节核对。若 Git 属性或归档变换改变了文件清单或字节，明确失败并定位，不使用“忽略空白”“统一换行”等手段把差异当成相同。

## 4. 本地静态检查

以下为后续文件存在后的命令示例，本轮编制设计时不执行。示例覆盖首版四页与已有报告；如果快照还有其他 HTML，实施时也要枚举检查。

```bash
python3 skills/static-page-builder/scripts/check_static_html.py \
  --root artifacts/static-portal/public \
  --page . \
  --page pages/reports/ \
  --page pages/tools/ \
  --page pages/about/ \
  --page reports/513310/2026-11-20/ \
  --base-path /static-pages/ \
  --output scratch/static-portal/static-formal-base.json
```

再使用实际或明确标注的本地模拟预览 base，检查**相同文件集合与字节**。不要为通过第二次检查而写另一套候选内容。

`--require-homepage-link` 适用于门户四页和首页实际展示的内容，不应不加区分地要求全部历史深层页面都从首页直接可达。目录入口可承担历史内容导航。

额外核对 CSS `url()`、相对资源和所有文件的实际 HTTP 返回；现有检查器不完整解析间接 CSS 和 JavaScript 动态加载，不能以它通过就宣称这些范围全部正确。

## 5. 浏览器检查

| 场景 | 最低检查 |
| --- | --- |
| 375、768、1440 宽度 | 无非预期横向溢出，文字、卡片和按钮可读 |
| 四个门户页面 | 导航、当前页状态、内容层级与 footer 一致 |
| 手机导航 | Tab 可到达按钮，Enter／Space 按控件原生行为操作，展开状态与内容一致 |
| 键盘阅读 | 跳转链接、可见焦点、合理次序，无明显焦点陷阱 |
| 报告流程 | 首页或报告目录能进入真实报告，返回门户关系正确 |
| 工具空状态 | 没有误导为可执行功能的入口 |
| 运行请求 | 本地资源正常，无未计划的 CDN、字体、表单或统计请求 |
| 截图 | 回读手机与桌面截图，修正后重新检查受影响页面 |

用正式和嵌套预览两种挂载进行。使用来源映射时明确记录，不能让测试跳到真实线上旧页面冒充候选内容。若本地环境缺字体或浏览器，记录限制，不能把空白截图或 DOM 模拟当作视觉通过。

本版没有搜索、评论或联系表单，不将这些记为已完成能力。浏览器检查属于所执行场景，不作完整无障碍认证承诺。

## 6. 在线预览验收

实施时准备真实 PR 编号和明确的预期预览 SHA。下面变量均取自实际操作记录，不能用模拟编号；示例本轮未执行。

```bash
python3 skills/static-page-publisher/scripts/verify_deployment.py \
  --base-url https://wvliteam.github.io/static-pages/ \
  --preview-pr "$PREVIEW_PR" \
  --preview-sha "$REVIEWED_PREVIEW_SHA" \
  --task static-portal \
  --output scratch/static-portal/preview-verification.json
```

通过条件：

- 对应运行成功，manifest 的 PR head 与目标版本相同。
- 预览模式对该任务记录文件的生成后哈希核验通过。
- 四个门户页面、镜像报告和资源在真实 base 下可用。
- 在线预览含自动生成状态标记，干净源中没有手写标记。
- 正式站点尚未因未确认候选而改变。
- 交付 URL、完整 SHA、完成和未完成检查，按现有规则确认具体版本。

预览 HTML 与源文件存在注入差异，不能用线上预览 HTML 与干净源直接要求相同。确认后门户源与正式门户源则要求按映射保持相同字节。

## 7. 合并与正式部署验收

### 7.1 收录前

- 从确认版本取得门户文件清单与干净源哈希，不自动改成后续 PR head。
- 对 HTML、CSS、JS、图标和许可全部比较。
- 只应用受管增量，保留报告、工具、其他页面和在 main 新出现的无关内容。
- 检查 `.nojekyll` 正式文件保留，部署保留目录不存在于源。
- `git ls-files artifacts` 对最终待合入状态无输出；不得仅因为工作区目录存在就删除它。
- 完整 diff、路径、数量和 README 更新正确，适用检查通过。

### 7.2 正式 HTML

`TARGET_MAIN_SHA` 是此次明确要验收的 main 提交，来源于实际合并与受信构建记录，并与目标 main 核对；不直接照抄待验证 manifest 的版本作为预期值。

```bash
python3 skills/static-page-publisher/scripts/verify_deployment.py \
  --base-url https://wvliteam.github.io/static-pages/ \
  --main-sha "$TARGET_MAIN_SHA" \
  --page . \
  --page pages/reports/ \
  --page pages/tools/ \
  --page pages/about/ \
  --page reports/513310/2026-11-20/ \
  --local-root docs \
  --output scratch/static-portal/production-verification.json
```

该命令只证明所选 HTML 的版本和字节。它当前没有 `--all`，也不会自动核对这些页面的全部 CSS、JS 和图标。

### 7.3 正式非 HTML 资源

逐项读取门户受管清单中的资源与许可：

1. 确认 manifest `main_sha` 仍为目标版本。
2. 对每个正式相对路径发只读 GET，记录 URL、状态和响应内容。
3. 比较实际响应 SHA-256、manifest `production_sha256` 和本地已确认文件字节。
4. 任一缺失、错误页、版本漂移或哈希不符，都不能报告完整验收成功。
5. 保存结果到 scratch；如需要等待缓存或运行完成，采用有界重试并保持目标 SHA 不变。

首版可用一次性只读检查完成，不以新增通用验证器为门户上线前置。若后续合入 R04 的完整资源模式，再更新长期命令和相应测试。

## 8. 关键负例与回退

| 负例 | 应有结果 |
| --- | --- |
| 资源使用错误域名根路径 | 正式／嵌套检查发现错误，不以正式单路径通过放行 |
| public 含 `.nojekyll` 或其他不合规隐藏成员 | 候选预检明确拒绝，保留正式控制文件 |
| 迁移时报告正文被修改 | 哈希比较失败，阻止门户收录夹带变化 |
| 审阅后 main 新增另一份报告 | 受控增量保留该报告，不能用旧快照同步删除 |
| 确认后门户 CSS 改动 | 识别源哈希变化，按对应版本规则重新核对 |
| tracked artifacts 仍在待合并树中 | main-ready 不通过，正常预览仍可保留 |
| HTML 正确但 Bootstrap JS 返回错误页 | 资源核验失败，不能以首页 200 作为成功 |
| 只写入 gh-pages、部署 job 失败 | 报告部署失败，保留实际运行证据 |
| 门户回退时出现新工具 | 只回退门户相关增量，保留后续内容 |

测试中的破坏性负例在隔离临时目录执行，不改真实历史内容。回退使用明确的新提交或定向 revert，重新验证导航和正式文件；不改写共享 main 历史。

## 9. 交付记录

| 记录 | 必须包含 |
| --- | --- |
| 基线 | main SHA、文件清单、原报告哈希 |
| 候选 | 任务目录、门户写入清单、镜像范围、源文件哈希 |
| 检查 | 实际执行的静态、路径、浏览器结果及未执行范围 |
| 确认 | 具体预览 SHA 与真实授权依据的引用 |
| 正式 | main SHA、运行 URL、正式 URL、HTML 与资源验证结果 |
| 维护 | 依赖版本、许可位置、升级与回退说明 |

原始日志、截图和本机路径留在忽略目录。公开记录只保留适合公开的版本与结论，不写入账户资料、凭据或工作区绝对路径。
