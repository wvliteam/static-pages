## 2. 已明确的设计决策

1. 门户首版为首页、报告目录、工具目录、关于页；没有真实工具时使用明确空状态。
2. 普通页面遵守 `pages/<slug>/index.html`，不直接将 PoC 的扁平 HTML 与测试文章搬入生产。
3. 必要资源本地化并放在 `assets/portal/`，独立报告与工具保持原路径、布局和字节。
4. 同一套干净文件支持正式与嵌套预览路径，不引入站点生成器或按 base 重建。
5. 门户预览使用完整可浏览快照；正式收录只应用明确的门户增量，不全量替换已有 docs。
6. `.nojekyll` 留在正式源，预览快照排除该隐藏控制文件；现有部署过程继续负责生成控制内容。
7. 保留 builder 与 publisher 两个 skill，优先复用现有检查和发布机制，按实际需要补基础 CI。
8. 先用有限的手工 HTML 目录维护，不把通用比较框架、自动目录生成器或 Agent 平台作为首版依赖。

## 4. 对原优化计划的取舍

| 原工作项 | 本路线的处理 |
| --- | --- |
| R01 发布兼容性 | 仍需实施前核实当前事件策略和真实入口，按需最小修正 |
| R02 候选 CI | 优先保留低权限检查与 main 草稿隔离，不引入模板构建 |
| R03 通用迁移比较器 | 首版先用固定文件范围和完整哈希证据，通用工具暂缓 |
| R04 完整资源模式 | 保留资源核验要求；先用现有命令加只读资源记录，通用扩展独立推进 |
| R05–R07 Agent 配套 | 围绕实际交接和 skill 变更按需补充，不作为首版平台建设 |
| R08 自动目录 | 首版显式维护 HTML 入口，实际负担出现后再引入单一数据源 |
| R09 页面起点 | 直接复用已验证模板与资源，不另建完整设计系统 |
| R10 故障隔离 | 与门户页面解耦，按多预览真实运行情况另行评估 |
